# Field Notes editor (/admin)

Field Notes are written and published from **/admin** on the website. No code, no developer.

## For James and Marie: publishing a Field Note

1. Go to `https://<the site>/admin` and choose **Login with GitHub**.
2. Open **Field Notes**, then **New Field Note**.
3. Fill in **Title**, **Category** and a **Short excerpt** (one or two sentences for the list page).
4. **Hero image**: choose **Choose an image**, then upload a web JPG or WebP about 2,400 px wide (5 MB limit). Describe the picture in **Hero image description**.
5. Write or paste the article in **Article**. Use **Heading 2** for each section, the list buttons for checklists, **Quote** for a highlighted note, and the **+** button to add a photo or a Photografik library film.
6. Optional: SEO title, meta description, social image, related service and the button at the end.
7. Leave **Published** off while you are drafting. Choose **Publish → Publish now** to save. A draft is saved to the site files but never shown: it stays out of the Field Notes list, the sitemap and search engines, and its address returns "not found" on the live site.
8. When it is ready, switch **Published** on and save again. The site rebuilds automatically in about a minute and the article appears first in the Field Notes list.

Tips: do not change an article's URL name after publishing. Avoid street addresses and client names in image file names.

## How it works (for Codex / developers)

- Editor: [Decap CMS](https://decapcms.org) 3.16.3 (open source, Git-based), loaded only on /admin from unpkg with Subresource Integrity (`src/admin/decap.json`). No hosted CMS account.
- Content: one file per article, `content/field-notes/<slug>.md`, JSON front matter + Markdown body. Uploads go to `static/images/field-notes/` and are served at `/images/field-notes/...` (Vercel image optimisation makes the responsive sizes).
- Config is generated by the build (`src/lib/cms-config.js`) so categories, the library picker and the Git branch match the deployment. Commits go to the branch the deployment was built from (`VERCEL_GIT_COMMIT_REF`; override with `CMS_BRANCH`).
- Build rules (`src/lib/field-notes-core.js`): published articles are validated strictly (a broken published article fails the build, so the previous deployment stays live); an incomplete draft only warns. Production does not generate draft pages; review builds show them with a Draft banner.

### One-time setup still needed (owner action, not done by Claude)

1. Create a **GitHub OAuth App** under the Photografik GitHub account: homepage `https://www.photografikstudios.com`, callback `https://www.photografikstudios.com/api/cms-callback` (or the review alias while testing; a GitHub OAuth App allows one callback URL).
2. In Vercel project settings add `CMS_GITHUB_CLIENT_ID` and `CMS_GITHUB_CLIENT_SECRET` (Production; Preview only if testing on the review alias).
3. Give each editor (James, Marie) a GitHub account with **write** access to `photografikstudios/PS_website`. GitHub, not the website, decides who can save.
4. Note: Decap's GitHub sign-in asks for the `repo` scope, which lets the editor's token act on repositories that GitHub user can reach. Editors should use accounts that only need this repository.

Local testing without GitHub: run `npx decap-server` in the repository, build, serve `dist`, and open `http://localhost:<port>/admin` (Decap uses the local file system on localhost).
